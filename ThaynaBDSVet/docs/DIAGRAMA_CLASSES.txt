DIAGRAMA DE CLASSES - ThaynaBDSVet
=================================

MODELS
------
Tutor
  - id, nomeCompleto, documento, endereco
  - List<String> contatos
  - List<Animal> animais
  + Tutor()
  + Tutor(nomeCompleto, documento, endereco)   // gera id
  + Tutor(id, nomeCompleto, documento, endereco)

Animal
  - id, nome, documentoTutor, especie
  - raca, sexo, pelagem, idade
  - historicoVacinas, alergias, condicoesSaude
  - castrado, observacoes, anotacoes
  - List<Long> idsTutores
  + Animal()
  + Animal(nome, documentoTutor, especie)      // gera id
  + Animal(id, ... campos ...)

Setor
  - id, nome, descricao
  + Setor()
  + Setor(nome, descricao)                     // gera id
  + Setor(id, nome, descricao)

Produto
  - id, nome, valor, quantidade, setor
  + Produto()
  + Produto(nome, valor, quantidade, setor)    // gera id
  + Produto(id, nome, valor, quantidade, setor)

REPOSITORIES (List estatica)
----------------------------
TutorRepository / AnimalRepository / SetorRepository / ProdutoRepository
  + create(obj): obj
  + findAll(): List
  + findById(id): obj ou null
  + findByNome(nome): List
  + update(id, obj): boolean
  + delete(id): boolean

Pesquisas extras:
  Animal: findByEspecie, findByDocumentoTutor
  Tutor: findByDocumento
  Produto: findBySetor, findByFaixaDeValor

SERVICES
--------
Validam regras e chamam o Repository.
Nao leem Scanner.

CONTROLLERS
-----------
Leem Scanner, tratam NumberFormatException, chamam Service.

APP
---
Menu com switch e tratamento de opcao invalida.

RELACIONAMENTOS
---------------
Tutor (1) ---- (N) Animal
Animal (N) ---- (N) Tutor   (mesmo animal em varias fichas)
Setor (1) ---- (N) Produto  (pelo nome do setor)
